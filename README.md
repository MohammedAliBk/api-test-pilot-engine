# API Test Pilot - Minimal Test Engine

A small Python engine that reads declarative JSON test cases, sends HTTP requests, compares the actual HTTP status with the expected status, and prints a JSON report.

## 1. Requirements

- Python 3.10+
- Network access to the API being tested
- Authorization to test that API

## 2. Install

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

## 3. Configure the test suite

Edit `example.json` and replace `https://api.example.com` with the base URL of an API you are authorized to test. The example host is only a placeholder.

```json
{
  "api": {
    "base_url": "https://api.example.com"
  },
  "test_cases": [
    {
      "id": "TC001",
      "description": "Verify that retrieving users returns HTTP 200",
      "request": {
        "method": "GET",
        "path": "/api/users"
      },
      "expected": {
        "status_code": 200
      }
    }
  ]
}
```

## 4. Run

```bash
python engine.py example.json
```

Write the report to a file:

```bash
python engine.py example.json --output report.json
```

Set a request timeout:

```bash
python engine.py example.json --timeout 5
```

## 5. Example result

```json
{
  "summary": {
    "total": 1,
    "passed": 1,
    "failed": 0,
    "errors": 0
  },
  "results": [
    {
      "test_id": "TC001",
      "description": "Verify that retrieving users returns HTTP 200",
      "status": "PASS",
      "expected_status": 200,
      "actual_status": 200,
      "duration_ms": 84,
      "error": null
    }
  ]
}
```

`duration_ms` is measured at runtime, so it will vary. The engine does not fake the result: it sends a real request. A network/DNS/timeout failure is reported as `ERROR`, not `FAIL`.

## Supported request fields

- `method`: GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS
- `path`: relative path under `api.base_url`
- `headers`: optional object of string header values
- `params`: optional query-parameter object
- `json`: optional JSON request body
- `expected.status_code`: required expected HTTP status

## Safety notes

- Test only APIs you own or have explicit permission to test.
- Do not execute Python or shell code generated by the AI. This engine only interprets the limited JSON fields above.
- Redirects are disabled, and absolute URLs in individual test paths are rejected.
- Before exposing this as a service, add a strict host allowlist and network-level blocking of loopback, private, link-local, and cloud metadata addresses to protect against SSRF. Apply request rate limits and concurrency limits too.
